# End-to-end test run: bugs and gaps

The whole stack in Docker (`docker compose -f docker-compose.yml -f docker-compose.test.yml up`), seeded, driven by Playwright (`apps/web/e2e`). Started 2026-10-22, during the feature freeze.

Severity: **S1** blocks a core flow, **S2** wrong behaviour or a security weakness, **S3** confusing or broken state, **S4** polish.
Status: open, fixed (PR), gap (needs a feature, listed only).

| # | Sev | Area | What happens | Status |
|---|-----|------|--------------|--------|
| 1 | S2 | Docker | `ollama-pull` pulls `LLM_MODEL` even when `LLM_PROVIDER=openai_compat`, so a hosted `gpt-oss:120b` started a 65 GB local download. | open (fix drafted: pull the chat model only for `ollama`) |
| 2 | S3 | Sign-in | After 5 tries a minute the sign-in form says "Wrong email or password" (and the code step "That code didn't work") for the rate-limit 429, so a person with the right password thinks it's wrong. | fix verified in browser (shows "Too many tries") |
| 3 | S2 | Docker | Nothing runs the scheduled jobs in Docker: files are never indexed for the assistant, no follow-up reminders, no purges, no metrics snapshots. | open (fix drafted: `jobs` service running `scripts/jobs.sh`) |
| 4 | S1 | Recommendations | No screen creates a recommendation, an action or a finding. The APIs exist (`POST /api/projects/:id/recommendations`, `/api/recommendations/:id/actions`, `/api/projects/:id/findings`) but nothing in the UI calls them, so the core flow can't start from the browser. | gap? (wiring only, no backend) |
| 5 | S2 | Clients | No screen lists or edits client contacts (`/api/clients/:id/contacts`, `/api/contacts/:id`), though meeting invites use them. | gap? |
| 6 | S3 | Actions | Firm-only action notes (`/api/actions/:id/notes`) have no screen. | gap? |
| 7 | S4 | Docker | Seeding inside Docker isn't documented; `db:seed` needs the full web env. | open (test override adds a `seed` service) |
| 8 | S1 | Security | Sign-in and two-factor rate limits are keyed on the client-sent `X-Forwarded-For`, and nothing in front of the app overwrites it. Rotating the header gives unlimited password guesses and unlimited TOTP guesses (7 tries with 7 header values: no 429; with one value: 429 from the 6th). | open |
| 9 | S2 | Sign-in | Better Auth's window restarts on every call, and in Docker every browser arrives from the same gateway address. Five sign-ins in a row, each less than a minute apart, lock everyone out until a full quiet minute passes (an office behind one NAT address hits this). | open |
| 10 | S2 | Security | Auth forms have no `method`, so a submit before the page finishes loading (slow link, quick typist, password manager) does a GET: `/sign-in?email=…&password=…`. The password lands in the address bar, history and server logs. Same for the invite, reset-password and security forms. | open (fix: `method="post"`) |
| 11 | S3 | Review | Accepting an action while an evidence-list item is still open fails with "Someone else changed this action. Reload to see the latest." The server's reason ("every evidence request must be accepted or waived first") is dropped: every 409 maps to "conflict". Same pattern in FormDialog's `callApi`. | open |
| 12 | S3 | Evidence | "Submit for review" with a file doesn't answer the open evidence-list item, so the firm sees the file in History but the item stays "Waiting", and verify is then refused (see #11). The owner has to know to use the item's own "Send a file" button. | open (UX) |
| 13 | S4 | Revision | After "Request revision" the owner gets "Resume work" but no "Submit for review"; sending again needs two steps. Expected, but nothing on the page says so. | open (UX) |
| 14 | S4 | Evidence | On a verified action the firm sees the client's evidence-list hint ("What the consultant asked you to send…"): `canManage` turns false once verified, and the hint follows it instead of the viewer's side. | open |
| 15 | S4 | Intake | Inquiry history runs the text into the date: "The public form sent the inquiryOct 22, 2026". | open |
| 16 | S3 | Dates | Discovery sessions and meetings are entered as "Time (Riyadh)" and shown in Riyadh time, but the form converts with the browser's own time zone (`localInstant` uses `new Date("…T10:00:00")`). From a browser on UTC, 10:00 is stored as 10:00 UTC and shown as 1:00 PM. Right only when the computer is set to Riyadh. | open |
| 17 | S3 | Notifications | No action event sends mail (assigned, revision requested, verified, evidence requested). Mail kinds are only accounts, meetings and inquiries, so an action owner who doesn't open Selah never hears they have work. | gap (needs a feature) |
| 18 | S2 | Docker | The web image never copies `public/`, so every logo is a broken image in Docker (`/brand/wordmark-*.png`, `/brand/mark.png` → 404): sign-in, inquiry form, sidebar. Every screen logs a 404 in the console because of it. Next's standalone output needs `public` copied next to `server.js`. | open (fix: one `COPY` line) |
| 19 | S4 | Access | A record the user can't open answers HTTP 200 (the loading skeleton streams first), then shows "Not found". No data leaks; but monitoring, crawlers and the access tests can't tell a denial from a page. | open (note) |
| 20 | S4 | Assistant | `/assistant?project=<id>` without `&case=` ignores the project and opens on the first project in the list, so a question can go to the wrong project. Only the "Ask the assistant" links (which carry a case) preselect. | open |
| 21 | S3 | Assistant | A plain question about a recommendation in the project ("What does approving the board charter need?") gets "I can't confirm that from the sources you can see": recommendations and actions only reach the model inside a case chat or a status question, not as searchable records. | gap? (records as passages) |
| 22 | S4 | Assistant | A new chat in the list says "in 1 second" (a time in the future): the list compares the server's timestamp with the browser clock. | open |
| 23 | S4 | Assistant | Each answer has an empty square where an avatar or icon should be; Arabic chat titles in the English list are cut at the wrong end ("…ما الذي طلبه"). | open |
| 24 | S4 | Assessments | The "Attach a project file" list shows bare names with no date or version, so the same name appears up to five times (draft.pdf ×3, minutes.pdf ×5). Section numbers start at 1 while question numbers start at 0 ("1. Company profile" holds "0.1"). | open |
| 25 | S2 | Actions | A consultant staffed on a project but not on that client's team (Noura on Al-Waha in the seed) gets "This page couldn't load. A server error occurred" on every action page of the project. The department picker asks for `department.read`, which needs the client assignment, and the thrown `ForbiddenError` takes down the whole page (React error #441 in the browser). | open |
| 26 | S3 | Layout | At 1024 px (tablet landscape) with the sidebar open, wide tables push the whole page sideways instead of scrolling inside their card: /inquiries (200 px), /actions (83 px), project pages (75 px), inquiry pages (28 px). Headers and the last columns are cut off. | open |
| 27 | S4 | Contrast | The red "Overdue: 2" count on the overview (Arabic, light) is 4.36:1 against its tinted background; WCAG AA needs 4.5:1. The only axe contrast failure across 238 screens. | open |
