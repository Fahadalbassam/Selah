# Tooltips and first-visit hints

Phase 2, part A (big prompt 6.1). Every tooltip Selah adds, where it shows and its text, for the handbook, the Selah map and anyone changing a screen. The texts live in `apps/web/messages/{ar,en}.json` under `tips`; this table is written from them (re-run the table when they change). `tests/tips.test.ts` checks that each one exists in both languages, is one short sentence, and that a status badge has one for every stored state.

## How a tooltip works

- `Hint` (`components/hint.tsx`) on the shadcn tooltip: it opens on hover **and on keyboard focus**, follows the reading direction, and is read out as the control's description. A button is its own trigger; a badge or a word is wrapped in a focusable span.
- One short sentence that says what happens or what something means, never the label again. Only where the label alone does not say it (6.1's list). Not on every element.
- Icon-only buttons never keep a mouse-only `title`: they have a tooltip (`tests/tips.test.ts` fails on an icon button with `title=`). Where the icon button's own name already says what it does (Rename chat, Zoom in, Close), the tooltip is that name, so the keyboard and the mouse read the same; they are not listed below.
- A status badge's tooltip names the exact stored state behind the word (docs/placement.md) and what it means for the reader; the client's side speaks to "your company".
- Existing hint texts now drawn as real tooltips (they were mouse-only `title`s): the observer badge on a project (`staffing.observingHint`), the client roles on a project's People tab (`clientRoles.about.*`), "Scanned" and "Text not readable" on a project file (`fileSummary.*`), and every `ApiButton` given a `title` (templates, meetings, inquiries, assessments).

## The handbook from Help

Help links each role to its own part of the handbook only (6.2): the client's people get **Open your guide** on Help (`/help/guide#client-admin`, `#client-manager`, `#action-owner`), firm staff (who have no Help page) get **Guide** in the menu under their name (`/help/guide#firm-admin`, `#consultant`). The page shows the client guide to the client's people and the firm guide to firm staff, never the other. The guides are written in `docs/handbook/{client,firm}/{ar,en}.md`; the web image is built from `apps/web` alone, so `npm run handbook:copy` copies them into `apps/web/src/lib/handbook-content.ts`, and `tests/help-in-app.test.ts` fails while the copy and the files differ. Until a guide is copied, there is no link and `/help/guide` is a 404.
