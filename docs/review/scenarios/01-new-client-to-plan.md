# Scenario 1. A new client from first contact to a working plan

Copy A (`SELAH_INSTANCE=scena`, `--full`, offset 40, app http://localhost:3040, mail http://localhost:8065). Arabic. Run on 20 Nov 2026 (a Friday) by helper 1. Synthetic data only. File used: `docs/review/scenario-files/sahm-plan.xlsx` (D6).

**PRIVACY findings:** none. Turki and a Sahm manager both got "Not found" for the Rawdah, Al-Nukhba, Al-Waha, internal and real-estate project URLs (step 23). Two things to know, both by design and not leaks: a consultant not staffed on a client still sees that client's name on the Clients page with a "request to join" button; and the "Not found" page is served with HTTP 200 (the page says «غير موجود»), so a script cannot tell found from not found by status code.

**Result: passed with friction.** Every step could be done in the app with no developer. Four real stumbles: (1) the plan import could not name any owner because the client's people are not in the project until someone adds them, and nothing in the invitation or department steps says so; (2) a consultant cannot set his own expertise; (3) "Make lead" is hidden under a row menu; (4) work mail is held until Sunday 07:00, so none of the "owner gets mail" checks can be seen on a Friday.

Click and time figures are per step. Page times under the development server are slow (a first dialog save is 8 to 15 seconds because the page compiles on first use; one step took 175 s); do not read them as production speed.

## Mail
Held work mail (all `action.assigned`, `inquiry.new`, and so on) is queued with a hold until **Sunday 22 Nov 07:00 Riyadh**: the trigger `hold_work_mail` holds it through quiet hours (20:00 to 07:00), Fridays and Saturdays by default. The page «خيارات البريد» explains this in plain words («لا يُرسل شيء يوم الجمعة...»). So on a Friday, "owners get action.assigned mail" cannot be observed. Proof it is queued: `outbound_emails` rows with `next_attempt_at` 2026-11-22 07:00 (hr x4, ops x4, owner, consultant). Invitation, password and meeting mail go at once (three invitations and the inquiry receipt arrived). Every mail body has Arabic, then English (checked on the invitation).

## Environment problem found while setting up (not an app bug, but worth fixing in `scripts/local.mjs`)
My first `--fresh --full` attempt failed with "port is already allocated" for the storage port. Docker had already created the other containers. The second attempt reused them, and three of them (the virus scanner, the PDF renderer and the local model) came up **without their published ports**. Result: the first upload said «فاحص الفيروسات غير متاح». Fix used: `docker compose ... up -d --force-recreate --no-deps clamav pdf-local` with the instance's port variables set. A re-run after a failed start should recreate containers whose ports changed.

## The four answers
1. **Could a real consultant or client have done this without help?** The firm side: nearly. The two places a person would stop are the missing "add the client's people to the project" step (19b) and Turki's empty expertise page. On the client side the first sign-in, notices and invitations are clear.
2. **Did anything break, lose data, show the wrong thing, or show something to the wrong person?** Nothing lost, nothing shown to the wrong person. Broken or wrong: Turki cannot edit his expertise (step 13); the review step lets an unknown owner through as a warning; the "release now" toggle did not take (21).
3. **Did Selah ever act like the consultant?** No. The qualification score says it is a guide; suggested consultants say "a suggestion only, the decision is yours".
4. **One change that would make it easiest:** when a lead invites people to a client, offer "add them to the project" on the same screen (or add all client people to a project by default and say so), so the plan import can name owners.
