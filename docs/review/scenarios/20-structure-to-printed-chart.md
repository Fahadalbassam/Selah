## The bug (confirmed, please fix first)
After version 1 is published the new draft cannot be edited, and the people panel stops loading after version 2. Evidence: `PATCH /api/org-chart/units/<id>` and `POST /api/clients/<id>/structure/units` return **400 `invalid input`**; the invitation with a position returns the same 400; the holders panel of a position says «لم تنجح العملية». The ids made at publish time are not valid UUIDs for the API's validator, for example unit `8660cc23-a53e-cc43-6dd2-83b2b18553d1` (version digit `c`, variant digit `6`) and position `53899613-8bd3-7cf7-34ab-68b208e73091`. In the database the draft rows made by the import have ids like `a9810ef3-3d79-405a-b5e3-ca96a900dd6a` (valid), and the copies made at publish time fail the regex `^[0-9a-f]{8}-[0-9a-f]{4}-[1-8][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`. The person sees only «تحقّق من البيانات المدخلة» or «لم تنجح العملية. أعد تحميل الصفحة وحاول مجدداً.», nothing tells them what is wrong. Screens: shots/20/10dbg2.png, 11dbg.png, 11p16.png. What still worked on the draft: Excel import into the draft («الإضافة إلى المسودة») made new rows with valid ids, which is how I made version 2.
