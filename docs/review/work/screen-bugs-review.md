## What is sound

- **Migrations.** `0080` redefines `check_recommendation_response()` with 0045's body byte for byte except `current_date` → `app_firm_today()`; `app_project_progress()` is 0047's body with the default changed only. `0081` is 0019's `app_action_ladder()` with `AND NOT s.firm_managed` added to the four client-role cases and nothing else; it now matches who `app_follow_ups_due()` (`0020_project_closure.sql:534-620`) can reach on a client without accounts. Grants, SECURITY DEFINER/INVOKER, volatility and `search_path` all survive (checked in `pg_proc`). Both tests fail on the old definitions.
- **B3.** `actionLadder()` returns no steps unless the status is in `OPEN_STATUSES` (draft, verified and closed excluded), for every role; `ReminderLadder` draws nothing then. Tested for staff and the owner.
- **B4.** `DepartmentsSwitch`: the switch only when `canManageDepartments` (firm admin, client admin); consultants and managers read "On/Off" ("مفعّلة/متوقفة"). Render test in both languages.
- **N12.** `SlidingCount` forwards `dir="ltr"` to the digit row (render test proves the attribute and "17"); both former `SlidingNumber` uses are replaced, no other remains.
- **N13.** The count is (project memberships ∪ projects of clients the person leads or deputises) ∩ projects the reader gets back under RLS and `project.read`. A hidden project is never counted; the lead now sees his own projects. Tested for consultant, outsider and client manager readers. Admins see `PeopleAdmin` (no count), so the hint line appears only with the table.
- **N27.** Text matches `app_can_extend()` apart from finding 8.
- **Midnight.** As above; the test is built to bite at any hour (UTC-12 and UTC+14 sessions).
- **N24 recording.** `recordFor = firmView && firmRun(...)` (`actions/[id]/page.tsx:161`); the evidence-list "Send a file" uses the same voice. Client roles and normal clients send exactly what they sent before (`receivedPayload(false, …)` is `{}`). The server still refuses a missing way or day (`progress.ts:14-20`) and a future day (`set_record_source()`, `0002:539-561`, firm day); the dialog maps both refusals to messages. The date picker disables days after the firm's today. Observers get no button (`authorize.ts:56-63`).
- **N24 texts and ladder.** The firm-run wording appears only where `panelVoice()` is `FirmRun`; none of it says the client signs in, sends or reads anything (unit test). The history line shows only for `consultant_recorded` rows.
- **Small faults.** Pitch = draft client project (`src/db/schema/app.ts:236-238` defines it so), firm-only. Plural ICU correct in both languages (Arabic zero/one/two/few/many/other). Data-sharing card hidden when there is no indicator and no planned or active project (tested both ways). "Available to assistant" uses `authorize("assistant.query")`, which for client people requires `principal.clientAssistant` (`authorize.ts:36-38`), so a reader sees it only when an assistant answers them; it reveals no setting they do not already see in their sidebar. Text boxes follow the page while empty.
- **Messages.** `ar.json` and `en.json` have identical key sets; the 19 new keys exist in both. No accepted legal text changed: `legal.terms`, `legal.privacy` and `legal.ai_notice` still read "صِلَة" and `LEGAL_VERSIONS` (`src/lib/legal.ts:11-15`) is untouched. The changed legal entries are the reference documents (`data_agreement`, `subprocessors`, `security`), which carry no version and need no acceptance.
- **Walkthrough.** `docs/walkthrough.md` lines 115-118, 150 and 174 match the seed: three late actions released already late with no date history, one approved move (the matrix), matrix items "one answered (submitted), one open". The seed test runs the real seed and checks both.
- **Docs.** `rules.md`, `accounts.md`, `engagement.md`, `indicator-data.md` updated where the change makes them untrue (with the exceptions in findings 4 and 10).
